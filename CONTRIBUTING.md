# Contributing to isotrail

Thanks for your interest in `isotrail`! Bug reports, ideas and pull requests are all welcome.

## Reporting a bug

Please [open an issue](https://github.com/ErykMajoch/isotrail/issues/new/choose) with the isotrail version (`isotrail --version`), your system, the command you ran, and the output with `-v`. A render showing the problem helps a lot. If you can, attach the scene bundle (`isotrail bundle hike.gpx -o hike.itb`) rather than the GPX file. You don't have to share your recording.

## Building

Install Rust with [rustup](https://rustup.rs/): the repository's `rust-toolchain.toml` selects the right toolchain, components and targets. On Windows, the build also needs the Visual Studio C++ build tools.

The toolchain is pinned to one Rust release, so CI and the release builds don't change compiler on their own. To move to a newer one, change `channel` in `rust-toolchain.toml`, then run the checks below, `sh web/build.sh` and the browser check (`node web/test/check.mjs chrome`) before opening a pull request. New lints often come with a new release.

```bash
cargo build                       # everything
cargo run -p isotrail-cli -- render fixtures/gpx/snowdon.gpx -o out.png
```

The workspace is split into crates:

| Crate | Contents |
| --- | --- |
| `isotrail-track` | GPX parsing, cleaning and statistics |
| `isotrail-bundle` | The scene bundle (`.itb`) types and file format |
| `isotrail-geo` | Projection, slab and grid, elevation and OpenStreetMap sources, landcover, caching |
| `isotrail-render` | The wgpu renderer. Meshers, camera, lighting, post-processing, text and overlays |
| `isotrail-export` | Rendering frames without a window, and PNG, GIF and MP4 output |
| `isotrail-cli` | The `isotrail` command |
| `isotrail-web` | The WebAssembly build of the renderer for web pages, driven by the `<isotrail-hike>` element in `web/` ([`web/README.md`](web/README.md)) |
| `isotrail-testkit` | Synthetic scenes, golden-image, GIF and video helpers for tests |

`isotrail-track`, `isotrail-bundle` and `isotrail-render` must stay WebAssembly-safe, meaning no filesystem, network or threads.

## Checks

Pull requests must pass the same checks as CI:

```bash
cargo fmt --all --check
cargo clippy --workspace --all-targets -- -D warnings
cargo test --workspace
cargo clippy --target wasm32-unknown-unknown -p isotrail-track -p isotrail-bundle -p isotrail-render -p isotrail-web -- -D warnings
cargo deny check
```

[`cargo deny`](https://github.com/EmbarkStudios/cargo-deny) checks the dependencies for security advisories, licences outside the list in `deny.toml` and crates from outside crates.io. Install it with `cargo install --locked cargo-deny`. A new dependency whose licence isn't on the list needs it added to both `deny.toml` and `about.toml`.

Release archives carry `THIRD-PARTY-NOTICES.md`, the licences of every crate in the binary and the web runtime, generated by [`cargo about`](https://github.com/EmbarkStudios/cargo-about) from `about.toml` and `about.hbs`. To see it locally, run `cargo about generate about.hbs -o THIRD-PARTY-NOTICES.md` (after `cargo install --locked cargo-about`), but don't commit the result.

CI also builds the web runtime with wasm-pack and fails if `isotrail-embed.js`, `pkg/isotrail_web.js` and `pkg/isotrail_web_bg.wasm` come to more than 3 MB gzipped. After `sh web/build.sh`, a local build of `isotrail embed` finds the runtime with `--runtime-dir web`.

The device limits are WebGL2's on every platform, so the native tests also catch anything the browser fallback couldn't draw.

Please don't add real recordings to the repository.

## Rendering in tests

Rendering runs on the GPU without a window. It uses a real GPU when there is one, and falls back to a software renderer otherwise. Set `ISOTRAIL_GPU` to `hardware` or `software` to choose. CI uses `software`: WARP on Windows, and Mesa lavapipe on Linux (the `mesa-vulkan-drivers` package). Tests take the GPU from `isotrail_testkit::gpu()`, which opens one device per test binary and lends it to one test at a time: lavapipe has crashed when every test opened its own at once.

Render tests compare their output with golden images in `fixtures/golden/`, and allow up to 0.5% of pixels to differ. When a comparison fails, the actual image and a diff are written to `target/golden-failures/`. After an intended change to the look, regenerate the goldens and review the new images before committing them:

```bash
UPDATE_GOLDENS=1 cargo test
```

The MP4 tests need `ffmpeg` and `ffprobe` on your `PATH`. Without them, they print a note and pass. CI installs ffmpeg on Linux.
